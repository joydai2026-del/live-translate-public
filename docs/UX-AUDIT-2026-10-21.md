# Hands-on UX audit, 2026-10-21

Two people, two screens, at the same time: a desktop host (Chromium 1280x800) and a phone guest (Playwright "iPhone 15", then "Pixel 7"), plus a third person (a second phone) for the multi-guest checks. Server: `PORT=5551 TRANSLATOR=mock node src/server.js` on the PR branch `chore/self-maintaining`. Guests opened the real join link the host page shows (the LAN address `http://192.168.1.50:5551/j/CODE`), not a test shortcut.

What was fake, on purpose:
- Speech: a fake `SpeechRecognition` replays text we push. It exercises the app's real recognition-result path (hold, interim, release, final, send), not real speech-to-text.
- Read aloud: `speechSynthesis.speak` is stubbed and every call is logged (text + voice language). No sound.
- Translation: the offline `mock` dictionary. Real translation quality was not tested (no paid API was called).
- Network drop: Playwright's `set_offline` did not close an already open event stream (lines kept arriving while "offline"), so the guest drop was redone with a local TCP proxy that really cuts every connection (row 25).

Scripts and raw results: `evidence/ux-audit-2026-10-21/*.json`. Screenshots: `evidence/ux-audit-2026-10-21/NN-function-device.png`. Every screenshot listed below was opened and looked at.

## Fixes (commits cc355ea and ab087d6)

1. Room full (row 29): `POST /guests` returning 429 is now a final error, not "offline". The guest sees a bilingual "no free reply slots" message and the unsent reply stays in the box. When the 429 comes from the per-network join limit instead (30 per hour per IP), the guest is told to try again in a few minutes, since Reset guests would not help (ab087d6, from the review). A 404 there ends the guest page. Test: `test/ux-audit.test.js` (fails before, passes after).
2. Host typed text in both-ways rooms (row 13): typed text is sent in the language it is written in (Chinese characters: Chinese, else English), the same rule guest replies already use. The mic toggle still controls speech. Test: `test/ux-audit.test.js` (fails before, passes after).
3. Header link tap target (row 36): `.top nav a` is 44 px tall.

## Suggestions for Rowan (design choices, not changed)

1. Keep the talk buttons in reach (row 37). On a 1280x800 laptop the first transcript line already pushes "Hold to talk" partly off screen; after a few lines it is gone and the host scrolls up every turn. Options: give the transcript its own scroll box, or a fixed talk bar at the bottom. Not changed because it is a layout decision and a planner-owned test (`checks/review-R2.test.js` M5) currently expects the page itself to scroll with a sticky banner.
2. Long messages (row 33): show a character counter or a "2000 characters max" note instead of silently cutting a paste.
3. In a full room, every reply attempt asks the server for a new reply key, which uses up the shared per-network join budget (30 per hour) faster on a busy Wi-Fi. Remembering "room full" until the next tap would avoid that.
4. Both-ways rooms on an English-language phone show the host's English as the big text by default (the phone's language decides). A first-visit "Which language do you read?" choice would make this obvious.

## Not testable and why

- Real speech recognition and its accuracy: needs a real microphone and Google/Apple speech services; a fake recognizer was used.
- Real translation quality: only the offline mock translator was used (no paid key, no outbound calls).
- Real camera QR scan and two physical devices on one Wi-Fi (client isolation): emulated devices on one machine; the QR content was verified to equal the link instead.
- On-screen phone keyboard covering the reply box (row 40), screen wake lock and screen-lock behaviour: not emulated by Playwright.
- Real iOS Safari and Android Chrome engines: both phones were emulated in Chromium.
